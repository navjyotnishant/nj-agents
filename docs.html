🔒 Nothing leaves your machine. Every skill runs in your current Claude session — no external API is called. The human always decides what gets committed; skills either advise, or write-then-propose.

The suites

Six classes of skill with different stances on touching your repo — from advise-only review to test source that runs. Both code-facing classes share one rule: the human decides what gets committed.

Six classes, one rule

Review
Advise only, leave no files, never commit. Reads your changes and reports. A gate subclass reviews a diff and returns PASS/WARN/BLOCK; a scan subclass (repo-maintenance) sweeps the whole tree for accumulated debt and returns candidates. Shared rules: CONVENTIONS.md.
Authoring
Writes an artifact into the repo (changelog, diagram, blog, screenshots, docs, a scaffolded project), then proposes the commit — never runs git add/commit/push/tag. Shared rules: CONVENTIONS-authoring.md §A1–A8.
Workflow
Reads the diff like review, invents nothing, proposes like authoring — but its artifact is a PR / commit message / release, not a repo file, so the placement rules don't apply. gh detected, never required.
PM-authoring
Writes a work item into your tracker (Linear/Jira/Notion/GitHub Issues), then proposes the create. Every item drafted to a standard — INVEST stories, Scrum Gherkin criteria & Definition of Done, SAFe Epic→Story→Task. Tracker-agnostic, MCP-detect-never-require, markdown fallback. Shared rules: CONVENTIONS-pm.md.
Social
Produces paste-ready copy for a published thing. Never writes to the repo, never auto-posts.
Testing
Writes test source into the repo and executes it — the only class that does both. Three clauses are machine-enforced by check.sh: T1 writes only inside detected test dirs, T2 never weakens or deletes an assertion, T3 requires an explicit non-prod base URL or it BLOCKs. Run state goes through bin/nj-run. Shared rules: CONVENTIONS-testing.md §T1–T14.
EM intelligence
Self-contained EM/vertical reports (class: is authoring under the hood — no seventh class swatch is emitted by frontmatter). See the EM reference.

Verdicts (review dimensions & gated pipelines)

PASS clean — safe to proceed
WARN only nits / warnings
BLOCK a real problem — stop
SKIP couldn't run — never a false PASS

Install & invoke

Skills are symlinked into a Claude Code config dir; invoke any one with its slash command. The installer globs the repo, so new skills/agents are picked up automatically.

# global (all projects) — symlinks into ~/.claude/
./install.sh
# another runner — gemini, codex, cursor, agents
./install.sh --runner gemini
# per-project — into DIR/.claude/
./install.sh --project /path/to/your/repo
# opt-in per-project push gate (runs the repo's own E2E suite)
./install.sh --git-hooks --project /path/to/your/repo
# remove (only symlinks pointing back into this repo)
./install.sh --uninstall

# then, in any repo:
/pre-push-review   # or /changelog, /arch-diagram, /docs-site, /pm-plan, /e2e-suite, ...
📎Idempotent, symlink-based (edit the repo → every install updates), and it refuses to clobber a real file. Reload Claude Code after installing.

How they work

Workflows drawn straight from the skill and agent definitions — the orchestration, the gates, and where a step can BLOCK.

Suite overview

37 skills across six classes and the 27 agents they orchestrate. You invoke a skill; it spawns the agents it needs.

/pre-push-review — secret gate, then parallel fan-out, then an HTML report

The secret scan runs first and alone; nothing is shared with any sub-agent until it clears. Then the five dimensions run in one parallel batch and aggregate; review-report-writer renders the result.

6
review-report-writer renders the report.

After the five dimensions aggregate, it builds a self-contained HTML report from the findings it is given — a verdict banner, per-dimension cards, findings by severity with file:line, and the run's scope / scanner / fleet. It renders the given findings only; it invents nothing.

/tech-blog — write → fact-check (BLOCK) → review → edit → polish → lint → post

A seven-agent pipeline. The fact-checker hard-blocks any claim it can't verify against the repo, looping back to the writer until every fact is grounded.

/capture-screenshots — capture → detect → redact → verify (BLOCK)

A redaction pipeline. The un-redacted original never leaves a gitignored dir; unproven coverage BLOCKs the write.

/pm-plan — decompose the tree, preview once, create parent-first

Turns a feature-sized ask into a tracked Epic→Stories→Tasks tree, tool-agnostic and draft-first. One approval covers the whole tree; a re-run reconciles rather than double-creating.

1
pm-decomposer builds a neutral tree.

Decomposes the ask into an Epic (SAFe hypothesis) → INVEST stories → done-when tasks — tracker-agnostic, no create yet.

2
Preview the whole tree.

The entire hierarchy is shown for a single approval — not one prompt per item.

3
Opt in, then create sequentially, parent-first.

Epic first, then its stories, then each story's tasks — wiring links as it goes (native sub-issues on GitHub).

!
Stop-on-partial-failure; reconcile on re-run.

Any partial failure stops and reports what was created. A re-run searches before creating (§P4), so it links to existing items rather than duplicating. No tracker connected → paste-ready markdown fallback.

/test-suite-author — plan → author → data, pausing at every stage

Ticket → cases → specs → fixtures in one run. Each stage is reviewed before the next consumes it. Writes only inside detected test dirs; proposes the commit, never runs git.

1
/test-plan — the case matrix.

Turns the requirement into equivalence classes, boundaries, negative paths, and authz cases; marks each new/covered/inferred. Pauses for review.

2
/test-author — specs in the repo's own framework.

Generates specs, enforcing a data-testid locator contract and flagging brittle selectors. Missing testids are proposed, not reached into app source. Pauses for review.

3
/test-data — per-spec fixtures.

Each spec owns its data — unique per run, cleaned up after; credentials from env, never on disk. Pauses for review.

!
Files the uncovered cases as tracker sub-tasks.

On approval, opens TEST--prefixed sub-tasks via /pm-task (search-before-create, so a re-run links rather than duplicates). Never commits — not with --yes, not in CI.

/e2e-suite — run, triage, weigh by history, report one verdict

The execution umbrella. Cost scales with failures, not specs — a green suite is nearly free. It never repairs anything.

!
/e2e-run captures the evidence.

Detects the repo's own runner and BLOCKS unless the base URL is explicitly non-prod, then captures trace/HAR/video/console into a gitignored temp dir. Raw artifacts never leave it.

2
/test-triage classifies each failure.

Real defect · test bug · environment · flake · data — with confidence and cited evidence. Never calls flake from a single run.

3
/flake-watch weighs by history.

Reads the committed flake ledger so a green run resting on known-flaky specs isn't scored the same as a clean one.

4
/test-report renders the matrix.

Requirement → case → spec → status → defect; leads with what is NOT covered.

→
One PASS/WARN/BLOCK.

A quarantined subagent forces BLOCK rather than being outvoted; a test bug is WARN, never PASS; ambiguity never resolves toward PASS.

Review suite — gate

AI-assisted review of your current commit or uncommitted changes. Advises only — never pushes, commits, or bypasses hooks.

/pre-push-review umbrella v0.4.0

Runs all five review dimensions — secret scan first as a gate, then the rest in parallel — and aggregates one verdict with a self-contained HTML report artifact. Supports non-interactive CI mode with an exit-code contract.

Invoke
/pre-push-review
Reviews
staged + unstaged + committed-but-unpushed changes
Requires
a git repo, a diff, and a secret scanner on PATH
Agents
correctness-reviewertests-build-runnerdependency-reviewerstyle-reviewersecrets-reviewerreview-report-writer
Expect
PASSWARNBLOCK + per-dimension table & HTML report
› Full flow

What happens

  1. Prints the AI-assisted banner; detects interactive vs. CI mode (NJ_AGENTS_CI=1).
  2. Builds the diff snapshot + diff hygiene (excludes lockfiles/binaries/generated; caps huge diffs to a partial top-N).
  3. Secret gate first — nothing shared with a sub-agent until it clears.
  4. Spawns correctness, tests/build, dependencies, style + the semantic security pass in parallel.
  5. Aggregates → one verdict; review-report-writer renders a self-contained HTML report (verdict banner, per-dimension cards, findings by severity + file:line, scope/scanner/fleet) — gitignored, no unmasked secrets.
  6. Optionally offers to wire a git pre-push hook — proposed, never silently installed.

Exit-code contract (hook / CI)

PASS/WARN → 0, BLOCK → non-zero. Still advises only — never runs git push.
