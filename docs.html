nj-agents

A personal, project-agnostic collection of Claude Code skills and agents for software-development workflows — installed into any project (or globally) via symlink. 12 skills, 20 agents across review, authoring, and social work.

🔒 Everything runs in your current Claude session — no external API is called, nothing leaves your machine. Every skill prints a banner describing what it does before it touches anything.

Install & invoke

Skills are symlinked into a Claude Code config dir; invoke any one with its slash command.

# global (all projects) — symlinks into ~/.claude/
./install.sh

# per-project — symlinks into DIR/.claude/
./install.sh --project /path/to/your/repo

# remove symlinks (only ones pointing back into this repo)
./install.sh --uninstall
./install.sh --project /path/to/your/repo --uninstall

# then, in any repo:
/pre-push-review        # or /changelog, /arch-diagram, /tech-blog, ...
./install.sh
Global install — links every skill + agent into ~/.claude/.
--project DIR
Installs into DIR/.claude/ instead, for a single repo.
--uninstall
Removes the symlinks. Safe — only touches links that point back into this repo; never deletes a real file or a link it doesn't own.
📎 The installer is idempotent and uses symlinks, so editing a skill in the repo updates every install. It refuses to clobber a real file that already sits where a link would go. Reload Claude Code after installing to pick up new skills/agents.

Two classes of skill

The two kinds take opposite stances on touching your repo. Both share one rule: the human decides what gets committed.

Review
Advise only, leave no files, never commit. Reads your changes and reports. Shared rules in CONVENTIONS.md.
Authoring
Writes an artifact into the repo (changelog, diagram, blog, screenshots), then proposes the commit — never runs git add/commit/push/tag. Shared rules in CONVENTIONS-authoring.md.

Verdicts

Review dimensions and gated pipelines report one of these. The umbrella aggregates them into a single overall verdict.

PASS clean — safe to proceed
WARN only nits / warnings — proceed with awareness
BLOCK a real problem (bug, secret, failing test) — stop
SKIP couldn't run (e.g. no test command) — never a false PASS

Review suite

AI-assisted review of your current commit or uncommitted changes, before you push (or on demand, or from CI). Advises only — never pushes, commits, or bypasses git hooks.

/pre-push-review umbrella v0.3.0

Runs all five review dimensions — the secret scan first as a gate, then the rest in parallel — and aggregates one verdict with a report artifact. Supports a non-interactive CI mode with an exit-code contract.

Invoke
/pre-push-review
Reviews
staged + unstaged + committed-but-unpushed changes
Requires
a git repo, a diff to review, and a secret scanner on PATH (gitleaks/trufflehog/detect-secrets)
Expect
PASSWARNBLOCK + a per-dimension table & report file
› Full flow & what to expect

What happens

  1. Prints the AI-assisted banner (nothing leaves your machine).
  2. Detects interactive vs. CI mode (NJ_AGENTS_CI=1 / --ci).
  3. Builds the diff snapshot and applies diff hygiene (excludes lockfiles/binaries/generated; caps very large diffs to a partial top-N review).
  4. Secret gate first — nothing is shared with any sub-agent until it clears (see /review-secrets).
  5. Spawns the remaining dimensions in parallel: correctness, tests/build, dependencies, style, plus the semantic security pass.
  6. Aggregates → one verdict; writes a timestamped report artifact (outside the repo tree / gitignored, no unmasked secrets).
  7. Optionally offers to wire a git pre-push hook — proposed, never silently installed.

Aggregate verdict

  • BLOCK — a secret is found, any dimension BLOCKs, or a required command fails.
  • WARN — only warnings / nits.
  • PASS — all clean (a SKIP or partial review is always called out — PASS-with-gaps ≠ PASS).

Example output

Dimension       Verdict   Top findings
Secrets         PASS      gitleaks: clean; semantic: clean
Correctness     BLOCK     off-by-one in pager (src/list.js:42)
Tests / Build   PASS      npm test: 128 passed
Dependencies    WARN      left-pad@^2 floating range
Style           WARN      leftover console.log (src/api.js:88)
OVERALL: BLOCK — fix the correctness blocker before pushing.

Exit-code contract (hooks / CI)

PASS/WARN → 0, BLOCK → non-zero. The suite still advises only — it never runs git push.

/review-secrets dimension v0.3.0

The security gate. Runs a required dedicated scanner over the diff first (hard gate), then a deeper semantic security pass.

Invoke
/review-secrets
Requires
gitleaks, trufflehog, or detect-secrets on PATH
Uses agent
secrets-reviewer
Expect
BLOCK on any secret or missing scanner · WARN hardening · PASS
› Full flow & what to expect

What happens

  1. Detects a scanner on PATH. If none is installed → BLOCK with install instructions (no heuristic-only fallback).
  2. Runs the scanner over added lines. Any credible hit → hard stop: prints file:line + pattern class + masked value, shares nothing.
  3. If clean, spawns secrets-reviewer for a semantic pass: injection, missing authz, unsafe deserialization, path traversal, SSRF, weak crypto, structurally-hardcoded secrets.
⚠️A missing scanner is a BLOCK, never a silent skip. Raw secret values are always masked, never echoed.
/review-correctness dimension v0.2.0

Reviews the changed lines and their blast radius for logic errors, regressions, unhandled edge cases, and missing validation.

Invoke
/review-correctness
Scope
changed lines + their callers/contracts — not the whole repo
Uses agent
correctness-reviewer
Expect
BLOCK real bug · WARN risky · PASS
› Full flow & what to expect

What it looks for

  • Off-by-one / boundary errors, null/undefined/None dereferences
  • Inverted or wrong conditionals; changed signatures/returns that break existing callers
  • Unhandled error/edge cases, missing validation on new inputs, resource leaks, concurrency hazards

Runs after the secret gate clears. Reports only high-confidence findings (≥80), each with a concrete failure scenario and fix.

/review-dependencies dimension v0.2.0

Governance review of dependency & license changes: added/removed/upgraded packages, version-pinning risk, license shifts, supply-chain signals.

Invoke
/review-dependencies
Scope

Uses agent
dependency-reviewer
Expect
BLOCK · WARN · PASS · SKIP
› Full flow & what to expect

Flags

  • Typosquat / lookalike package names (a primary supply-chain vector)
  • Major-version bumps, suspicious downgrades, floating ranges (*, latest) added where the repo otherwise pins
  • Copyleft/strong-copyleft or unknown licenses entering a permissive codebase (flagged for legal/governance)
  • Removed dependency still used in the diff; changed registry/source URL; disabled integrity checks

Advises & flags — it does not adjudicate license compatibility.

Authoring suite

Generates documentation artifacts from your project and places them in the repo, then proposes the commit. Every skill reads the repo to ground its output — nothing is invented.

/changelog authoring v0.1.0

Generates/updates CHANGELOG.md in Keep a Changelog format + SemVer, from your commit history (Conventional Commits as the signal). Proposes the commit — never commits, pushes, or tags.

Invoke
/changelog
Writes
CHANGELOG.md at repo root (merges into [Unreleased])
Uses agent
changelog-writer
Expect
a suggested version bump + a proposed git commit block you run yourself
› Full flow & what to expect

What happens

  1. Determines the range: since the last git tag, or the existing changelog's latest entry, else full history.
  2. Parses Conventional Commits → suggests a bump (feat→minor, fix→patch, !/BREAKING→major). You can override.
  3. changelog-writer groups into Added/Changed/Deprecated/Removed/Fixed/Security, de-dupes, drops noise (wip/merge/fixup), rewrites terse subjects into user-facing prose.
  4. Merges into [Unreleased] (never clobbers released sections), maintains compare link refs.
  5. Proposes the commit — plus an optional, clearly-marked release-only git tag line it never runs.

Reads your README/docs/ADRs, then generates a system / solution / sequence / data-flow / deployment / ER diagram, places it in docs/architecture/, and proposes the commit.

Uses agent
diagram-architect
Expect
a .excalidraw + .svg in docs, embedded, + a proposed commit
› Full flow & what to expect

What happens

  1. Resolves diagram type and format.
  2. Ingests architecture docs (README, ARCHITECTURE, docs/, ADRs) and skims entry points to ground the diagram.
  3. diagram-architect builds a structured model (nodes/edges/boundaries) → emits valid .excalidraw JSON + a matching self-contained SVG (so it renders on GitHub without the Excalidraw app).
  4. Places it per the placement ladder, embeds the SVG, proposes the commit.
🖼️View the .svg on GitHub; open the .excalidraw at excalidraw.com to edit. Nothing in the diagram is invented — every box/arrow traces to the repo.
/capture-screenshots multi-agent v0.1.0

Captures from a running web app, terminal/CLI output, a static HTML/component, or existing images — then runs a redaction pipeline so nothing sensitive ships. Only the redacted image is committed.

Invoke
/capture-screenshots
Writes
redacted images to docs/images/; raw stays gitignored
Uses agents
screenshot-capturersensitive-data-reviewerscreenshot-redactor
Expect
before/after + a list of every redacted region; a proposed commit
› Full flow & what to expect

Pipeline

  1. Capture — screenshot-capturer grabs the raw image (web via Playwright with discover-per-repo launch/auth, terminal, static, or existing). Never fabricates credentials.
  2. Detect — sensitive-data-reviewer marks PII/secrets (emails, tokens, keys, phone, cards, SSNs, names, hostnames) with regions + risk class.
  3. Redact — screenshot-redactor blurs via sharp/jimp: full/solid box for high-risk, partial mask for low-risk illustrative data.
  4. Verify gate — confirms every flagged region is obscured; if it can't verify coverage, it BLOCKS the write.
🛡️Redact by default. The un-redacted original is never committed — it stays in a gitignored .screenshots-raw/. High-risk secrets are always fully obscured.
/tech-blog multi-agent v0.1.0

A pipeline (writer → fact-checker → reviewer → editor → final-polish → platform-lint → optional poster) that writes an expert technical post about the project. The fact-checker BLOCKS on any claim it can't verify against the repo.

Invoke
/tech-blog — give a topic/angle & audience
Writes
docs/blog/<slug>.md + publish-ready MD/HTML (HTML via pandoc if present)
Uses agents
blog-writerblog-fact-checkerblog-reviewerblog-editorblog-final-polishblog-platform-lintblog-poster
Expect
a grounded post; a proposed commit; posting only via a connected MCP (or Dev.to REST fallback) you opt into
› Full flow & what to expect

Pipeline

  1. Deep repo ingest + discovers any /arch-diagram outputs to embed.
  2. blog-writer drafts to the scratchpad, citing each claim's source.
  3. blog-fact-checker verifies every claim against the repo — hard-blocks on anything wrong or unverifiable until it's fixed or cut.
  4. blog-reviewer critiques structure/clarity/depth → blog-editor finalizes, embeds diagrams, adds front-matter.
  5. blog-final-polish runs a pre-publish mechanical checklist; blog-platform-lint checks the target platform's rules (Dev.to first) before posting.
  6. Writes to docs/blog/ + publish-ready copies; blog-poster creates a draft only if you opt in — via a publishing MCP or a Dev.to REST fallback (never auto-publishes).
✅Nothing is invented: every fact traces to your repo, or it doesn't ship.

Auto-derives the menu from the content, grounds everything in the source (flags gaps rather than inventing), and embeds auto-redacted screenshots via /capture-screenshots.

/docs-site
Inputs
docs/markdown · the codebase · a topic/outline · definition files (any/all)
Uses agents
docs-architectdocs-designer
Expect
a browsable docs.html with sidebar nav; gaps flagged; a proposed commit
› Full flow & what to expect

What happens

  1. Resolves inputs + scope (docs, code, outline, definition files) and the audience.
  2. Ingests the sources into a content model (parses structured definition files exactly).
  3. docs-architect auto-derives the menu/sections from the content, writes grounded copy, and flags gaps ("not documented") instead of inventing.
  4. If a page needs UI/terminal images, it delegates to /capture-screenshots — so embedded shots are PII/secret-redacted and the raw never lands in the repo.
  5. docs-designer builds the self-contained page (sidebar nav, tiered content, light/dark, zero external deps; reuses an existing design system if present).
  6. Writes docs.html (or docs/index.html), proposes the commit.

Social

Promotional copy for a published thing — grounded in the real content, handed to you to post. Not review, not authoring-into-the-repo; it produces paste-ready copy and never auto-posts.

/social-post social v0.1.0

Drafts LinkedIn / X promo copy for a published URL (blog, repo, demo) — hook-first opener, correct link + preview-card strategy, clean hashtags, in short / medium / builder-story variants. Grounded in the actual linked content; never invents claims. Hands you copy to paste — never auto-posts.

Invoke
/social-post — give a published URL
Platform
LinkedIn (default) or X/Twitter
Uses agent
social-post
Expect
short / medium / builder-story variants + hashtag line + first-comment block
› Full flow & what to expect

What happens

  1. Fetches the URL and grounds the copy in what the piece actually says (no invented metrics/claims).
  2. Confirms angle (builder story / problem hook / announce), primary CTA, and style prefs.
  3. Applies feed-algorithm mechanics: hook in the first ~2 lines; the link whose preview card you want goes first; secondary links move to a ready-to-paste first comment (multiple body links suppress reach); platform-appropriate hashtag count & form.
