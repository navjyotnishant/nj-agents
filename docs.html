The suites

Two classes of skill with opposite stances on touching your repo — plus a social class that produces copy you post. Both code-facing classes share one rule: the human decides what gets committed.

Two classes, one rule

Review
Advise only, leave no files, never commit. Reads your changes and reports. Shared rules: CONVENTIONS.md.
Authoring
Writes an artifact into the repo (changelog, diagram, blog, screenshots, docs), then proposes the commit — never runs git add/commit/push/tag. Shared rules: CONVENTIONS-authoring.md.
Social
Produces paste-ready copy for a published thing. Never writes to the repo, never auto-posts.

Verdicts (review dimensions & gated pipelines)

PASS clean — safe to proceed
WARN only nits / warnings
BLOCK a real problem — stop
SKIP couldn't run — never a false PASS

Install & invoke

Skills are symlinked into a Claude Code config dir; invoke any one with its slash command. The installer globs the repo, so new skills/agents are picked up automatically.

# global (all projects) — symlinks into ~/.claude/
./install.sh
# per-project — into DIR/.claude/
./install.sh --project /path/to/your/repo
# remove (only symlinks pointing back into this repo)
./install.sh --uninstall

# then, in any repo:
/pre-push-review   # or /changelog, /arch-diagram, /docs-site, ...
📎Idempotent, symlink-based (edit the repo → every install updates), and it refuses to clobber a real file. Reload Claude Code after installing.

The secret scan runs first and alone — nothing is shared with any sub-agent until it clears. Then the other dimensions run in a single parallel batch and aggregate to one verdict.

/tech-blog — sequential pipeline with a blocking fact-check

Writer → fact-checker → reviewer → editor is strictly sequential (each transforms the prior). The fact-checker is a hard gate: it loops back to the writer until no claim is wrong or unverifiable. The finalize checks after the editor run in parallel, then the optional poster and promo.

Review suite

AI-assisted review of your current commit or uncommitted changes. Advises only — never pushes, commits, or bypasses hooks.

/pre-push-review umbrella v0.3.0

Runs all five review dimensions — secret scan first as a gate, then the rest in parallel — and aggregates one verdict with a report artifact. Supports non-interactive CI mode with an exit-code contract.

Invoke
/pre-push-review
Reviews
staged + unstaged + committed-but-unpushed changes
Requires
a git repo, a diff, and a secret scanner on PATH
Expect
PASSWARNBLOCK + per-dimension table & report
› Full flow

What happens

  1. Prints the AI-assisted banner; detects interactive vs. CI mode (NJ_AGENTS_CI=1).
  2. Builds the diff snapshot + diff hygiene (excludes lockfiles/binaries/generated; caps huge diffs to a partial top-N).
  3. Secret gate first — nothing shared with a sub-agent until it clears.
  4. Spawns correctness, tests/build, dependencies, style + the semantic security pass in parallel.
  5. Aggregates → one verdict; writes a timestamped report (gitignored, no unmasked secrets).
  6. Optionally offers to wire a git pre-push hook — proposed, never silently installed.

Exit-code contract (hook / CI)

PASS/WARN → 0, BLOCK → non-zero. Still advises only — never runs git push.

/review-secrets dimension v0.3.0

The security gate. A required dedicated scanner runs over the diff first (hard gate), then a deeper semantic security pass.

Requires
gitleaks, trufflehog, or detect-secrets on PATH
Agent
secrets-reviewer
Expect
BLOCK on secret or missing scanner · WARN · PASS
› Full flow
  1. No scanner installed → BLOCK with install instructions (no heuristic-only fallback).
  2. Scanner hit → hard stop: file:line + pattern class + masked value, shares nothing.
  3. Clean → spawns secrets-reviewer: injection, missing authz/IDOR, unsafe deserialization, SSRF, weak crypto, hardcoded secrets.
/review-correctness dimension v0.2.0

Reviews changed lines and their blast radius for logic errors, regressions, unhandled edge cases, and missing validation.

Scope
changed lines + callers/contracts — not the whole repo
Agent
correctness-reviewer
Expect
BLOCK real bug · WARN · PASS
› What it looks for
  • Off-by-one / boundary, null/undefined/None derefs, inverted conditionals
  • Changed signatures/returns that break existing callers; unhandled edge cases
  • Missing validation on new inputs; resource leaks; concurrency hazards

High-confidence findings only (≥80), each with a concrete failure scenario + fix.

/review-tests-build dimension v0.2.0

Auto-detects and runs the repo's own test/lint/build commands. Never hardcodes a stack; never installs tooling.

Detects
Node, Python, Go, Rust, JVM, Make/just — or commands in CLAUDE.md/AGENTS.md
Agent
tests-build-runner
Expect
BLOCK a fail · PASS · SKIP none found
› Detection order
  1. Commands documented in CLAUDE.md/AGENTS.md/README
  2. Node scripts → task runners (just/make) → Python → Go → Rust → JVM
🚫Missing tooling is reported, not installed. Nothing detected → SKIP.
/review-dependencies dimension v0.2.0

Governance review of dependency & license changes — added/upgraded packages, pinning risk, license shifts, supply-chain signals.

Scope
manifest changes only — no network, no install
Agent
dependency-reviewer
Expect
BLOCK · WARN · PASS · SKIP
› Flags

  • Major bumps, downgrades, floating ranges added where the repo pins

Consistency & hygiene: does new code match the conventions around it, are commit messages clean, is there leftover debug output.

Authoring suite

Generates artifacts from your project and places them in the repo, then proposes the commit. Nothing is invented — everything traces to the source.

/changelog authoring v0.1.0

Generates/updates CHANGELOG.md in Keep a Changelog format + SemVer from your commit history (Conventional Commits as the signal). Proposes the commit — never commits, pushes, or tags.

Writes
CHANGELOG.md (merges into [Unreleased])
Agent
changelog-writer
Expect
a suggested version bump + a proposed git commit block
› Full flow
  1. Determines range: last git tag / existing changelog / full history.
  2. Parses Conventional Commits → bump (feat→minor, fix→patch, !/BREAKING→major). You override.
  3. changelog-writer groups Added/Changed/…, de-dupes, drops noise, rewrites into user-facing prose.
  4. Merges into [Unreleased] (never clobbers released sections); proposes commit + optional release-only tag.
/arch-diagram authoring v0.1.0

Reads your README/docs/ADRs, then generates a system/solution/sequence/data-flow/deployment/ER diagram, places it in docs/architecture/, and proposes the commit.

Format
default Excalidraw + exported SVG; also mermaid, inline SVG, or Figma (MCP)
Agent
diagram-architect
Expect
a .excalidraw + .svg in docs, embedded, + a proposed commit
› Full flow
  1. Resolves diagram type + format; ingests architecture docs to ground it.
  2. diagram-architect builds a structured model → valid .excalidraw JSON + a matching SVG.
  3. Places & embeds it; proposes the commit. Every box/arrow traces to the repo.
/capture-screenshots multi-agent v0.1.0

Captures from a running web app, terminal/CLI, a static HTML/component, or existing images — then runs a redaction pipeline so nothing sensitive ships. Only the redacted image is committed.

Writes
redacted images to docs/images/; raw stays gitignored
Agents
screenshot-capturersensitive-data-reviewerscreenshot-redactor
Expect
before/after + a list of every redacted region; a proposed commit
› Pipeline
  1. Capture — grabs the raw image (never fabricates credentials).
  2. Detect — marks PII/secrets with regions + risk class.
  3. Redact — full/solid box for high-risk, partial mask (or placeholder) for illustrative.
  4. Verify gate — unproven coverage BLOCKS the write.
🛡️The un-redacted original is never committed — it stays in a gitignored .screenshots-raw/.
/tech-blog multi-agent v0.1.0

A pipeline (writer → fact-checker → reviewer → editor → final-polish → platform-lint → optional poster) that writes an expert technical post. The fact-checker BLOCKS on any claim it can't verify against the repo.

Writes
docs/blog/<slug>.md + publish-ready MD/HTML
Agents
blog-writerblog-fact-checkerblog-reviewerblog-editorblog-final-polishblog-platform-lintblog-poster
Expect
a grounded post; a proposed commit; posting only via a connected MCP (or Dev.to fallback) you opt into
› Pipeline
  1. Deep repo ingest + discovers /arch-diagram outputs to embed.
  2. blog-writer drafts (cites each claim) → blog-fact-checker hard-blocks wrong/unverifiable claims, looping to the writer.
  3. blog-reviewer critiques → blog-editor finalizes (embeds diagrams, front-matter, terminology/emphasis passes).
  4. blog-final-polish (mechanical checklist) + blog-platform-lint (platform rules) run, then optional blog-poster draft.
✅Nothing is invented: every fact traces to your repo, or it doesn't ship.
/docs-site multi-agent v0.1.0

Universal documentation generator (it built this page). From existing docs, the codebase, an outline, or structured definition files (SKILL.md/OpenAPI/JSON-Schema): auto-derives the menu, grounds everything in the source (flags gaps), embeds auto-redacted screenshots via /capture-screenshots.

Inputs
docs · codebase · outline · definition files (any/all)
Agents
docs-architectdocs-designer
Expect
a browsable docs.html; gaps flagged; a proposed commit
› Full flow
  1. Resolves inputs + scope; ingests into a content model (parses definition files exactly).
  2. docs-architect auto-derives sections, writes grounded copy, flags gaps.
  3. If a page needs UI shots, delegates to /capture-screenshots (auto-redacted).
  4. docs-designer builds the self-contained page; proposes the commit.

Agent
social-post

short / medium / builder-story variants + hashtag line + first-comment block
› Full flow
